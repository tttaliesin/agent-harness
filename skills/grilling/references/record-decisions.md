# Record resolved decisions

When the user asks to record an interview's conclusions, update the repository's existing domain glossary, decision log or OpenSpec change.
Record settled terms and consequential decisions where their owners already maintain them; link instead of copying the same requirement into multiple documents.
Use the domain-modeling skill when available for glossary or ADR work, otherwise follow the repository's existing format.
Create an ADR only for a consequential trade-off whose reason would otherwise be lost.
Do not scaffold a tracker, instruction-file tree or a full documentation set merely to record an answer.
Keep unresolved choices visibly unresolved and preserve the user's authorized scope.

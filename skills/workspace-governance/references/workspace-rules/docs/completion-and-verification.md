# 완료와 검증 기준

- 시작할 때 사용자가 관찰할 완료 결과와 이미 승인된 납품점을 짧게 확인하고 인계·리뷰에서도 유지
  작은 작업에는 대화 맥락으로 충분하며 별도 계획서나 재승인 의무 없음
  새 요청이나 목표 달성을 막는 결함이 드러나면 근거와 달라진 범위를 명시
- 추가 검증 전에 판단할 완료 조건, 변경 영향의 구체적 실패 가능성, 적용되는 필수 검사와 결과가 바꿀 다음 결정을 확인
  해당 근거 없이 결과가 결정을 바꾸지 않는 검증은 추가하지 않고, 개별 검사뿐 아니라 현재 작업을 계속할 필요도 함께 재평가
- 목표 달성이나 안전한 전환을 실제로 막는 결함은 기존 권한 안에서 수정
  일반화·추가 커버리지·관련 없는 개선은 자동 완료 조건으로 추가하지 않고, 일정이나 효율을 이유로 필요한 안전 검증과 필수 검사·납품을 생략하지 않는 원칙
- 최종 관련 코드·입력·환경과 증거의 유효성이 유지되면 기존 실행 증거 재사용
  새 변경·실패·증거 무효화·필수 검사 요구가 있으면 영향을 받는 범위만 재검증
  별도로 적용되는 필수 fresh 실행 gate와 실제 운영 직전의 변동 가능한 상태 확인은 유지
  리뷰어 교체 자체는 재실행 이유가 아님
- 검증 수단의 신뢰성 조사는 실패 exit 전달 누락·오래된 산출물·상충 결과 등 구체적 의심 근거가 있을 때 해당 결함과 영향 범위로 제한
  검증 수단의 보완을 무관한 복구·예외 일반화로 확대하지 않는 원칙
- 같은 실패가 반복되거나 새 정보를 얻지 못하면 반복 실행에 앞서 가설·방법·범위를 재평가하고 현재 성과와 남은 장애를 설명
  시간·횟수만으로 실패를 완료 처리하거나 모든 기술 판단을 사용자에게 넘기지 않고 독립적인 승인 범위의 작업은 계속 수행
- 완료 조건·적용되는 필수 검사·승인된 납품이 충족되면 완료 보고
  선택적 미실시 검증은 필요한 경우 한계로 남기고 새로운 완료 의무로 추가하지 않는 원칙
  필수 지침과 충돌하면 해당 근거와 영향을 밝히고 소유자에게 해결을 요청하며, 해결 전에는 충돌한 의무를 조용히 생략하지 않는 원칙

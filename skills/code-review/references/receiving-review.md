# Assess review feedback

Read this when responding to findings, before changing the implementation.

1. Identify the claimed behavior, supporting evidence and the requested change.
2. Check the current code, requirement and candidate; a stale review may no longer apply.
3. Verify whether the finding is correct and whether the proposed fix preserves required behavior.
4. Implement supported fixes within the authorized scope and run the relevant checks.
5. Explain disagreements with concrete code or test evidence and report remaining uncertainty.

Clarify only ambiguities that materially block a dependent change; continue independent authorized fixes.
Preserve the agreed delivery endpoint and do not add speculative features to satisfy an unsupported suggestion.
External replies require the user's authorization for that communication; permission to fix code alone does not authorize posting comments.

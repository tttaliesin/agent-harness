# Domain documentation

Read the repository's existing glossary, context map, and relevant decisions through AGENTS.md and Core/OpenSpec pointers before exploring the affected area.
If CONTEXT.md or CONTEXT-MAP.md exists, use it for domain terms.
Read relevant ADRs where the repository stores them.
Missing optional documents do not block work.

Use the established vocabulary in code, tests, review findings, and specifications.
Resolve contradictory terms through [domain-modeling](../domain-modeling/SKILL.md).
Record a resolved term lazily in the existing glossary when documentation edits are authorized.
Use OpenSpec and the repository's design records for implementation decisions; avoid duplicating an existing decision in a second workflow.

Surface a conflict with an accepted architectural decision explicitly, with the evidence and tradeoff.
Preserve the current approval and delivery scope while resolving it.

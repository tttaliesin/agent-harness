# 외부 스킬 개인 수정 메모

이 저장소 밖에서 관리하는 스킬의 개인 수정 의도와 적용 범위 기록
외부 패키지의 관리 주체와 설치 위치를 유지하며, 업데이트 시 현재 원문과 대조한 뒤 필요한 변경만 재반영

## 2026-09-12 적용

사용자의 스킬 병목 정리 요청에 따라 현재 사용자 설치본에 적용한 변경
모델의 성능 개선을 실측한 결과가 아닌, 불필요한 중단·고정 절차·중복 지침을 줄이는 정책 수정

| 대상 | 현재 적용 버전 | 변경 의도 |
| --- | --- | --- |
| OpenAI Docs | 시스템 설치본 | 로컬 설정·오류는 설치된 상태부터 확인하고, 최신 제품 동작·API 계약·명시적 문서 질문에는 공식 근거 확인 |
| Skill Installer | 시스템 설치본 | 현재 권한에서 가능한 작업은 진행하고, 필요한 경우에만 호스트가 지원하는 승인 경로 사용 |
| Documents | `26.909.12148` | 일반 작성의 템플릿 선택 요청 생략, 편집 묶음 단위 렌더링과 변경 영향에 비례한 시각 검증 |
| PDF | `26.909.12148` | 최종 결과의 필요한 시각 검증 유지, 확인한 결과를 미적 대안 때문에 반복 수정하지 않는 종료 기준 |
| Presentations | `26.909.12148` | 템플릿 선택·장식 이미지의 조건부 적용, 문장 부호·수동태의 일괄 금지 대신 문맥과 정확성에 따른 판단 |
| Spreadsheets·Excel Live | `26.909.12148` | 요청한 동시 비교를 위한 명시적 시나리오 계산 허용, 엔진·대상 지원을 확인한 수식 선택, 필요한 참조만 로딩 |
| Excel Live | `26.909.12148` | 최신 세션 탐색과 대상 통합문서의 읽기 성공을 연결 근거로 사용하고, 누락·실패한 준비 단계에만 UI 진단 적용 |
| Visualize | `1.0.37` | 호스트의 진행 알림 지침 준수, 문맥 압축 후 필요한 출력 계약과 활성 시각화 지침만 복원 |
| Deep Research | `0.1.15` | 결과를 바꾸는 정보만 질문하고, 분량과 부가 데이터 파일을 요청·근거·재사용 목적에 맞춰 결정 |
| Plugin Management | `0.1.0` | 실제 사용 가능한 도구와 호출 조건에 따른 검색·추천·관리, 특정 도구명이나 설치 권한 가정 제거 |

현재 패키지에 필요한 실행 API, 인증·권한 경계, 원본 보존, 계산 오류 검사, PDF 양식 필드 검증 유지
DOCX·PDF의 새 문서·광범위한 레이아웃 변경·기존 시각 검증 근거가 없는 경우 전체 페이지 검사 유지
국소 수정은 유효한 기존 검사 근거가 있을 때 변경 페이지와 영향을 받은 페이지 흐름을 확인하고, 영향이 불명확하면 검사 확대
수식 지원은 실제 엔진과 납품 대상에서 확인하고, 재계산·내보내기 결과를 검증한 범위만 지원으로 판단

같은 작업에서 이 저장소의 Mermaid·Markdown 정본과 사용자 설치본에도 변경 반영
Mermaid의 사람 승인·렌더링 성공 선행 조건은 사용자나 대상 저장소가 명시적으로 요구한 경우에 적용하고, 일반 로컬 문서 작성은 수행한 검사와 미확인 범위를 밝혀 완료
Markdown 참조 문서와 Mermaid 예제의 중복 승인 지시도 같은 기준으로 정리
한국어 문체, Mermaid의 Unicode 표현 선호와 PlantUML 선택 조건은 기존 계약 유지

외부 시스템·플러그인 패키지는 업데이트나 재설치로 개인 수정이 덮어써질 수 있는 범위
이 문서는 승인된 수정 의도의 유지보수 기록이며 자동 패치·동기화 도구가 아니므로, 새 버전의 도구 계약과 원문을 확인한 뒤 재반영
Second Brain 관련 원본 정리는 사용자가 지정한 workspace-rule 프로젝트의 별도 작업

### 검증 범위

변경한 Markdown 36개 파일의 구조·링크 검사와 정본 Git diff 공백 검사 통과
Mermaid·Markdown 정본의 변경 파일 8개와 사용자 설치본의 내용 일치 확인
현재 CLI 앱 서버에서 수정 스킬 10개의 활성 상태, 폐지 스킬 2개의 비활성 상태와 스캔 오류 없음 확인
Deep Research·Plugin Management는 현재 세션에 제공된 설치 경로에 반영했으나 별도 CLI 앱 서버 목록에는 나타나지 않아 해당 파일의 구조 검사까지 확인
공식 `quick_validate.py`는 번들 Python의 PyYAML 부재로 실행 불가하여 스킬 등록 검사와 frontmatter 보존 검사로 보완
기존 HTML 영역은 Markdown 검사기의 범위 밖이며 이번 변경에서는 해당 영역 미수정

독립 시나리오 검토에서 일반 로컬 Mermaid 작성, 명시적 렌더링·팀 승인 조건 보존, 시나리오별 동시 재계산 설계, 기존 시각 검증 근거를 활용한 국소 DOCX 검증 확인
검토에서 발견한 시트 예제와 스타일 문서의 단일 계산 모델·선택기 강제 지시도 함께 정리
실제 Office 산출물 생성·Excel 연결 실행·처리 시간 비교는 미실시

## 2026-09-05~06 참고 기록

아래 항목은 과거 수정·검토 기록이며 현재 설치본에 반영되어 있다는 보장은 없는 상태
현재 지침과 비교할 때 참고하며 자동 적용 금지

| 스킬 | 수정 의도 |
| --- | --- |
| doc-coauthoring | 사용자가 대화식 공동 작성을 요청한 경우에만 단계별 확인 사용; 일반 작성 요청은 완성 초안까지 진행 |
| find-skills | 적합한 스킬이 없어도 이미 요청한 작업은 가능한 도구로 계속 수행; 검색만 요청했다면 검색 결과만 보고 |
| OpenAI Docs | 사용자 지침 검토는 로컬 파일부터 확인; 최신 제품 동작에 의존하는 주장에 공식 문서 확인 적용 |
| PDF | 최종 렌더링·이미지 검사는 유지하되, 내용 누락·겹침·읽을 수 없는 글자·잘못된 값 등을 해결한 뒤 미적 선호만으로 반복 수정하지 않기 |

이미 받은 승인은 같은 대상과 작업 범위에서 재사용한다.
새로운 검색 범위나 명시적 승인 조건까지 생략하는 의미는 아니다.
PDF 렌더링이나 검사가 불가능하면 검증 완료로 전달하지 않고 현재 산출물과 확인하지 못한 범위를 알린다.
